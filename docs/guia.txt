GUIA PARA NOTEBOOKLM
PRESENTACION DEL PROYECTO F1 CON ARQUITECTURA MEDALLON Y MODELO ESTRELLA

Objetivo del material
=====================

Genera una presentacion profesional, clara y academica sobre el proyecto de analitica historica de Formula 1.

La presentacion debe explicar:

1. La arquitectura medallon del proyecto.
2. La funcion de cada capa: f1, f1_silver, f1_gold, f1_gold_star y f1_control.
3. Por que Gold no debe duplicar Silver.
4. Por que se creo un esquema separado llamado f1_gold_star.
5. Como se debe representar visualmente el modelo estrella.
6. Como el dashboard Streamlit consume la capa Gold.
7. Que valor de negocio entrega el modelo.

Tono esperado
=============

Usa un tono profesional, tecnico y claro.

La audiencia puede ser profesor, jurado academico, equipo de datos o personas de negocio con conocimiento basico de bases de datos.

Evita sonar informal.
Evita sobrecargar las diapositivas.
Cada diapositiva debe tener poco texto y una explicacion oral sugerida.

Resumen del proyecto
====================

El proyecto trabaja con datos historicos de Formula 1.

La arquitectura sigue un patron medallon:

f1
  Capa base con datos historicos cargados en Databricks.

f1_silver
  Capa curada. Limpia, normaliza y enriquece los datos.
  Contiene dimensiones y hechos detallados.
  Incluye reglas analiticas como:
  - piloto ganador,
  - podio,
  - clasificacion,
  - abandono,
  - salida desde pole,
  - puntos de carrera,
  - puntos sprint,
  - shared drive.

f1_gold
  Capa Gold de consumo.
  Contiene marts de negocio, KPIs y vistas ejecutivas.
  Es la capa que alimenta el dashboard Streamlit.
  No debe duplicar Silver ni guardar detalle tecnico innecesario.

f1_gold_star
  Modelo estrella fisico separado.
  Se crea para herramientas BI, modelado dimensional y visualizacion clara en DBeaver/Databricks.
  Se construye desde f1_gold, no desde f1_silver.

f1_control
  Capa de control.
  Guarda historicos/versionamiento de snapshots de KPIs.

Mensaje central
===============

El proyecto no es solo un dashboard.
Es una arquitectura de datos completa:

datos historicos -> curaduria -> consumo ejecutivo -> modelo dimensional -> control historico.

La decision profesional mas importante es separar f1_gold y f1_gold_star:

- f1_gold conserva los productos de datos listos para consumo.
- f1_gold_star expone esos productos en forma dimensional para BI.

Esto evita contaminar Gold y evita duplicar Silver.

Diapositiva 7 - Por que crear f1_gold_star
------------------------------------------

Contenido:
f1_gold_star se crea separado de f1_gold para tener un modelo dimensional fisico.

Razones:
- Permite ver claramente dimensiones y hechos.
- Facilita consumo BI.
- No contamina la capa Gold.
- No duplica la capa Silver.
- Se construye desde marts Gold.

Notas del presentador:
El modelo estrella no debe ser una copia del detalle Silver. Debe representar objetos de negocio ya curados y agregados desde Gold.

Resumen ejecutivo para usar como voz narrativa
==============================================

Este proyecto implementa una arquitectura medallon para datos historicos de Formula 1. La capa Silver normaliza y enriquece los datos. La capa Gold transforma ese detalle en marts, KPIs y vistas ejecutivas. Para facilitar el consumo por herramientas BI, se crea un esquema separado llamado f1_gold_star, que materializa un modelo estrella construido desde Gold. Esta separacion evita duplicar Silver, mantiene limpia la capa Gold y permite presentar una arquitectura profesional, gobernada y orientada a consumo analitico.
